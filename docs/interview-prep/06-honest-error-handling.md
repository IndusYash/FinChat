# FinChat — Gate 5: Honest Error Handling and ResearchMemo Disclosure

**Date:** October 29, 2026  
**Scope:** Elimination of silent fallbacks in document ingestion/search, and correction of unverified claims in ResearchMemo  
**Status:** Complete — TypeScript compilation clean, Vite build passes, API error path tests verified  

---

## 1. Executive Summary

In Gate 4's feature reality check, two critical credibility defects were identified in the user-facing UI:
1. **Silent Fallback Anti-Pattern in RagVault:** `uploadDocument()` and `searchKnowledgeBase()` in `frontend/src/services/api.ts` intercepted HTTP failures and network errors, silently fabricating successful upload objects (with synthetic chunk counts) or swallowing search errors. In `RagVault.tsx`, a failed PDF upload was added to the document table as "INDEXED ✓", giving the user a false impression that their document had been processed into FAISS.
2. **Unsupported Verification Claims in ResearchMemo:** `ResearchMemoModal.tsx` claimed `"VERIFIED DETERMINISTIC AUDIT • ZERO HALLUCINATED MATH"` and `"CONFIDENTIAL // INSTITUTIONAL EQUITY RESEARCH"`, despite computing DCF via a static multiplier (`stock.price × 1.036`), hardcoding Monte Carlo VaR at `-12.4%`, and quoting a fixed regulatory citation.

In Gate 5, both issues were repaired:
- `api.ts` now throws meaningful errors on HTTP 4xx/5xx and network failures.
- `RagVault.tsx` displays explicit error banners, never creates fake indexed documents on failure, and labels previous results when a search fails.
- `ResearchMemoModal.tsx` clearly labels all model estimates, DCF figures, and risk corridors as illustrative sample templates and qualifies the sign-off footer.

## 2. Files Changed and Technical Analysis

### 2.1 `frontend/src/services/api.ts`
- **`uploadDocument()`:**
  - Removed client-side fallback `estChunks` computation that fabricated `status: 'success'` when offline or on server error.
  - Added strict `if (!res.ok)` validation extracting backend error details (`errBody?.detail`) or HTTP status.
  - Now returns a rejected promise / throws `Error(detail)` on any failure.
- **`searchKnowledgeBase()`:**
  - Removed silent `try/catch` block that caught exceptions and returned `[]`.
  - Added HTTP status check; throws `Error(detail)` when `!res.ok`.
  - Safely extracts `data?.results` array or returns empty array on valid 200 responses.

### 2.2 `frontend/src/pages/RagVault.tsx`
- **Upload Flow:**
  - Added `uploadError` state.
  - On upload failure, `handleFileUpload` sets `uploadError(message)`, clears `uploadSuccess`, and crucially **does not add a fake document to `docs`** or increment `docCount`.
  - Added visual error alert banner (`AlertCircle` icon with red alert styling) rendered directly below the uploader box.
  - Resets the file input value on completion to allow re-uploading after failure.
- **Search Flow:**
  - Added `searchError` and `isPreviousResults` states.
  - When `searchKnowledgeBase()` fails, `handleSearch` catches the error, sets `searchError(message)`, and if previous results exist, sets `isPreviousResults(true)`.
  - Renders an explicit warning banner: `⚠️ DISPLAYING PREVIOUS / BASE RESULTS (Latest search query failed)` so stale results can never masquerade as matches for the new query.
  - Displays a clean informational message when a valid search yields zero matches.

### 2.3 `frontend/src/components/ResearchMemoModal.tsx`
- **Footer Sign-Off:**
  - Replaced `VERIFIED DETERMINISTIC AUDIT • ZERO HALLUCINATED MATH` with:
    `ILLUSTRATIVE MODEL ESTIMATES • NOT CERTIFIED FINANCIAL ADVICE`
  - Replaced `GENERATED BY INVESTO // AUTONOMOUS QUANT ENGINE` with:
    `INVESTO RESEARCH TEMPLATE // DEMO MODE`
- **Metric & Section Headings:**
  - Modal title: `INSTITUTIONAL RESEARCH MEMORANDUM (ILLUSTRATIVE TEMPLATE)`
  - Letterhead: `SAMPLE TEMPLATE // EDUCATIONAL EQUITY RESEARCH`
  - Rating badge: `▲ BULLISH INTRINSIC RATING (ILLUSTRATIVE)`
  - Metrics grid: `DCF FAIR VALUE (SAMPLE)` with `${fairValue}.00 (${upside}% est.)`
  - Section 1: `1. DETERMINISTIC VALUATION SYNTHESIS (SAMPLE MODEL)`
  - Section 2: `2. STOCHASTIC VOLATILITY & 95% VALUE-AT-RISK (SAMPLE BENCHMARK)`
  - Section 3: `3. REGULATORY 10-K AUDIT & RISK CITATIONS (SAMPLE EXTRACT)`
- **Clipboard Export:**
  - `handleCopy()` text updated with `(ILLUSTRATIVE TEMPLATE)` headers, explicit sample parameter qualifiers, and a standard educational disclaimer.

## 3. Previous Behavior vs. Corrected Behavior

| Scenario | Previous Behavior | Corrected Behavior |
|:---|:---|:---|
| **PDF upload fails on server (HTTP 400/500)** | `api.ts` returned fake success object with estimated chunks; `RagVault` added document to table as "INDEXED ✓" and showed green success toast. | `api.ts` throws `Error(detail)`; `RagVault` renders red error banner with server error detail; no document added to table. |
| **PDF upload disconnected / network down** | Handled by silent catch block; fabricated fake indexed document. | Throws network error; UI shows clear failure banner; document table untouched. |
| **Search request fails (non-200 or timeout)** | Returned `[]` silently; user saw existing results with no indication that the new search failed. | Throws `Error(detail)`; UI displays red error banner and an explicit warning: `⚠️ DISPLAYING PREVIOUS / BASE RESULTS (Latest search query failed)`. |
| **Zero search results found** | Swallowed silently; previous results remained on screen. | UI displays "No matching passages found in knowledge base for this query." |
| **ResearchMemo footer** | Displayed misleading claim `"VERIFIED DETERMINISTIC AUDIT • ZERO HALLUCINATED MATH"` despite mock calculations. | Displayed honest disclosure: `"ILLUSTRATIVE MODEL ESTIMATES • NOT CERTIFIED FINANCIAL ADVICE"`. |
| **ResearchMemo metrics** | Presented as certified institutional calculations. | Explicitly labeled as `(SAMPLE MODEL)`, `(SAMPLE BENCHMARK)`, and `(ILLUSTRATIVE)`. |

## 5. Remaining Limitations

1. **Session Store Document Persistence:** In `RagVault`, uploaded documents are indexed in backend memory (`SESSION_STORES[session_id]`), which resets when the backend server restarts.
2. **ResearchMemo Dynamic Valuation:** The ResearchMemo modal currently operates on props passed from `currentStock` (mock snapshot data). Connecting the memo to the live `POST /api/analyze` output (so it uses real DCF valuation and real retrieved SEC citations) remains an area for future integration.
3. **Pinecone Index Initialization in Local Dev:** In local development without `PINECONE_API_KEY`, `POST /api/search` queries the local uploaded session chunks only and skips the institutional 2,400-page corpus.
